## כללי ברזל

1. **סשן נפרד לכל שלב.** אל תריץ P0 ו-P1 באותו סשן — הקונטקסט מתלכלך והסוכן מתחיל "לתקן" קוד תקין.
2. **אל תעבור שלב לפני שה-Verification עבר.** תנאי הכניסה לשלב N+1 הוא ה-definition of done של N.
3. **Plan mode לפני P2 ו-P3.** אלה השלבים האלגוריתמיים — תן לסוכן לתכנן, קרא את התוכנית, ואז אשר.
4. **אל תיתן לסוכן להחליש בדיקת איכות.** בשלושה מקומות יש quality gates (טוהר אשכולות ≥0.90,
   זיהוי ספייק ללא false positives, negativity ממוקד-ישות). הפרומפטים אוסרים במפורש להחליש אותן —
   אם הסוכן בכל זאת מנסה, זו הנקודה לעצור ולבדוק ידנית.
5. **סקור ידנית שלושה דיפים:** `pipeline/stance.py` (P2), `signals/scoring.py` + `weights.py` (P3),
   ו-`site/serializers.py` (P5). שם נקבע מה ייחשב "שלילי", מה ייחשב "חם", ומה בדיוק המערכת מפרסמת
   מתוכן של אחרים — שלוש החלטות מוצר, לא החלטות קוד.
6. **מגבלת 400 התווים ב-P5 היא לא באג.** אתר שמפרסם RSS של אחרים חייב לתת כותרת + תקציר קצר +
   קישור למקור, ולא יותר. יש בדיקה שאוכפת את זה — אל תיתן לסוכן לעקוף אותה.
